## Duplicate/legacy notes

- `POST /api/v1/withdrawals` is declared in multiple routers; inspect Express mount order before treating declarations as distinct APIs.
- `GET /api/v1/withdrawals` is declared in multiple routers; inspect Express mount order before treating declarations as distinct APIs.

The support module contains a legacy withdrawal router mounted after the P2P router at the same URL prefix. The P2P routes respond first for matching `/withdrawals` paths; the legacy POST implementation fails closed with `PAYOUT_PROVIDER_UNAVAILABLE`. Keep this as a cleanup/documentation concern, not a separate supported payout path.
